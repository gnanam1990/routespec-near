## WORKING_LOCAL determination

Resolved on this host by M14 (were BLOCKED in M12): process-tree containment of the subject
(`PROCESS_TREE_ENFORCED`, engine-verified), an independent interceptor launched and attested per
case in the installed path, trust-rooted (enrolled launcher key) build-registration, case-launch,
and interceptor-launch attestations through the standalone service, complete-effect INV-04 PASS
for the corrected build, per-case policies for multi-scenario corpora, and the export-boundary
termination test (RP-04).

Still unmet, so **`WORKING_LOCAL` is not claimed**:

1. **RP-05: no clean-checkout run on a real CI service.** The CI action ran only with a simulated
   runner environment from the clean install (M10, M12). A real run needs you to push
   (`docs/USER-NEXT-STEPS.md`).
2. **RP-08: declared-hooks-only and unconfined captures are not rejected as release evidence.**
   The product still promotes them with labelled limitations (M12 behaviour). The contained
   journey's capture is independently observed and confined, so it would pass such a check, but
   the rejection rule itself is not enforced at promotion. Changing it touches the console's
   promotion flow and is left as engineering work.
3. **RP-02/RP-06: the interceptor profile is not reviewed.** The interceptor artifact is the
   repository's canary interceptor pinned by digest and attested at every launch, but the
   profile record stays `DECLARED_UNREVIEWED`: the product has no profile review workflow, and
   no independent security review has happened (NOT_RUN).

Also true and recorded: one environment only (Windows host + Docker Engine in WSL 2); the trust
root is an operator key enrolled on the same machine (`LOCAL_LAUNCHER_KEY`); the launcher's
identity covers RouteSpec sources, not Node, the engine, WSL, or the kernel; the client-instance
digest and the registered profile digest are vouched as given by the launcher. RP-07 remains
BLOCKED on your provider JWT and is outside `WORKING_LOCAL`.
