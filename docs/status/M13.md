## Code migration (behaviour kept identical)

- zod: `z.string().datetime()` to `z.iso.datetime()`, `z.string().url()` to `z.url()`,
  `.passthrough()` to `.loose()`, `z.ZodIssueCode.custom` to `'custom'`; nested CI config
  defaults use `.prefault({})` so omitted `uploads` / `liveDry` blocks still get inner defaults.
- Issue codes in `RS_SCHEMA_INVALID` details (control API `fields[].code`, CI config `issue`,
  scenario compile and replay `issues`) are mapped back to the zod 3 codes by
  `stableIssueCode(issue, input)` in `packages/contracts/src/schemas/issues.ts`, including the
  two enum cases zod 4 changed (absent or non-string enum value is `invalid_type`; the one
  single-value enum, `transport_error.error`, is built with `singleValueEnum()` and still
  reports `invalid_enum_value`).
- `RS_PARTIAL_FINALIZATION` missing-value detection: `isMissingValueIssue(issue, input)` walks
  the input (zod 4 dropped `received`), and counts an enum given no value as missing, as zod 3
  did.
- react-router: imports move from `react-router-dom` to `react-router`; the v7 future flags the
  console already set are the v7 defaults, so the `future` prop is removed.
- Not identical, by design and recorded in ADR-0018: human-readable messages of issues without a
  custom message (diagnostics only; codes, paths and RouteSpec error codes are unchanged), and
  the console bundle size (JS 351.62 kB / 103.60 kB gzip before, 406.19 kB / 123.15 kB gzip
  after; no budget test fails).
