## Red / green evidence (honest account)

The API views, client changes, and pages were written before most of the real-service tests.
First runs against the real service failed, and these changed product code:

- `shell-real` axe (light and dark): **2 failed**, `color-contrast` on the first timeline event
  of a real case. Cause: the entrance animation faded text from opacity 0, so axe measured a
  row mid-fade. Fix: the animation moves position only (ADR-0014 §10).
- `shell-real` layout at 375 px: **1 failed**, body overflow 26 px on every run-operation page.
  Cause: the real coverage code `INDEPENDENT_INTERCEPTOR_NOT_SELECTED` did not wrap (the fixture
  used shorter strings). Fix: the missing-coverage list wraps long codes.
- Contract gaps found while wiring (fixed in product code before the real tests ran green):
  run-operation and import detail shapes, gate-run request body and mutation replies,
  timeline `kind` filter rejected by the API's strict query (now a server-side phase filter whose
  total is the filtered total), no `POST /imports`, promotion corpora run as BASELINE so
  `CORRECTED_RUN_*` could never be reached, recovery never offered for an expired lease.

Test-side corrections on first runs: matrix row read before the selection re-rendered;
ambiguous `Evidence` row locator; settings label for committed live; missing notice heading
role; recovery epoch arithmetic when another recovery had already fenced an expired case; a
CSP header probe that loaded pages without the token.

Mutation checks (one product change, owning test run, file restored; script outside the repo):

## Data, API, and schema changes

- Control API (additive): `detail-views.ts` (run-operation and import detail), `POST /imports`,
  `gateId` on gate-run views, recovery offered on expired leases, filtered event totals,
  lineage roles derived from persisted promotions. No migration; journal schema version stays 7.
- Runner (additive): `GateRunRequest.lineageRoleByScenario`.
- Console: request bodies and replies aligned with the API; new actions — finish case input,
  evaluate gate, plan export, save proposed mapping, review, promote with corpus label and
  severity, corrected-client rerun link that prefills the corpus; phase filter; schemas extended
  (all additions optional or present in the API).

## Security and privacy review

- The control token stays in memory, the fragment is removed, and only the theme is stored
  (re-verified on the real service). One-time case and reconciliation tokens are shown once and
  dropped on acknowledgement; the suite checks no token-shaped value reaches browser storage.
- Locator-like run-operation fields (recipient, refund, deposit address and memo) are masked by
  the API itself; the console never receives them.
- A secret-bearing upload is reduced to digest and finding classes by M05; the reply, the
  import row, and the page never contain the value (asserted).
- The acceptance service binds 127.0.0.1, sends the production CSP, and passes its token to
  Playwright workers through the environment only; nothing is written to disk but the
  temporary journal, which is deleted on stop.

## Known limits and remaining work

1. `CORRECTED_RUN_PASSED` is not reachable for the promoted scenario on this host: the mapping
   requires INV-04 (complete effect), which stays REVIEW without a process-tree sandbox and an
   attested build (EFFECT_COVERAGE_MISSING, UNATTESTED_BUILD). The console shows
   `CORRECTED_RUN_NOT_PASSING` from the server. BLOCKED with M04/M08.
2. Mapping editor: the workbench saves the service's proposed draft; field-by-field editing of a
   mapping is not built.
3. Export write from the browser is not offered (plan only); write with the CLI/API after
   confirming the plan digest.
4. Compare revisions, deletion dry-run, attester/effect-policy/manifest/inventory registration
   screens, and the dry-probe action are not built; the probe is BLOCKED by policy (M07 RP-07).
5. Live updates poll every 2 s; authenticated SSE is not built (M08 limit).
6. One session holds at most 8,191 events (M03 HARD_CAPS); 10,000 events are measured across
   the 100-case gate run.
7. Manual: screen-reader runs for T-049/T-050, high-contrast review, Firefox/WebKit, touch;
   T-052 (M12) is not claimed.
