# API and CLI specification

## 1. Conventions

- Control prefix: `/__routespec/v1`
- Proxy paths: the selected protocol profile exposes only enumerated 1Click-compatible paths.
- Content type: `application/json` unless noted.
- IDs: opaque lowercase UUID strings generated by the service.
- Amounts: base-unit decimal strings; never JSON floating-point numbers.
- Times: RFC 3339 UTC wall times and integer virtual milliseconds.
- Pagination: opaque cursor plus bounded `limit` from 1 to 200.
- Control authentication: ephemeral local bearer token. Proxy/observer authentication uses an ephemeral `X-RouteSpec-Case-Token` plus non-secret identity headers. Token values are returned once at case start/recovery, stored only as digests, and never returned in list/detail payloads.
- Unknown fields: rejected on mutation requests; additive fields may appear in response minor versions.
- Idempotency and concurrency: control mutations require `Idempotency-Key`; administrative, project, import, and export updates also require an expected optimistic revision/`If-Match`. Case/session execution mutations are fenced by token, client instance, and epoch. The versioned adapter sends stable `X-RouteSpec-Session`, `X-RouteSpec-Case-Run`, `X-RouteSpec-Logical-Job`, `X-RouteSpec-Request-Id`, `X-RouteSpec-Adapter`, and `X-RouteSpec-Fencing-Epoch`; after quote creation it correlates the returned `X-RouteSpec-Run-Operation` for quote finalization, commit, internal retries, and status. Every RouteSpec-local header is stripped before any live upstream request.

## 3. Error envelope

```json
{
  "error": {
    "code": "RS_MODE_POLICY_DENIED",
    "message": "The request is not permitted in LIVE_DRY_PROBE.",
    "requestId": "8e55ab68-41ed-46ac-997a-4bd027299c58",
    "recoverable": false,
    "details": {
      "method": "POST",
      "path": "/v0/deposit/submit",
      "upstreamAttempted": false
    }
  }
}
```

Messages are human-safe. Details never echo authorization values, raw signed payloads, or configured secrets.

## 4. Control API

### `POST /__routespec/v1/projects`

Creates a local project.

Request: name, optional description, retention policy. Response: immutable `projectId` plus current settings revision.

### `POST /__routespec/v1/projects/{projectId}/revisions`

Registers an immutable integration revision.

Required request fields:

- `revisionLabel`
- `commitSha` as a string or `null`
- `configurationDigest`
- `protocolProfileId`
- `metadata` restricted to declared scalar keys

The API calculates the revision identity; the caller cannot overwrite it.

### `GET /__routespec/v1/projects/{projectId}/revisions`

Lists revisions with gate summary and no secrets.

### `POST /__routespec/v1/projects/{projectId}/builds`

Registers a mandatory subject build identity containing revision ID, exact repository locator, commit SHA, dirty-tree digest, built-artifact digest, lock/toolchain digests, declared launch-recipe digest, required effect-manifest digest, and optional CI workflow/run identity. Registration is labelled `USER_ASSERTED_LOCAL`; it neither runs nor verifies a build and cannot support a verified-build claim.

### `POST /__routespec/v1/effect-manifests`

Registers an immutable versioned instrumentation manifest bound to one build/artifact and adapter revision. Each hook declares hook ID/revision, effect type, sink class, instrumentation mechanism, source locator digest where attestable, and scenario/capability selectors. Unknown fields are rejected. A caller declaration is `SELF_REPORTED`; attesting the digest binds identity but does not prove completeness.

### `POST /__routespec/v1/effect-coverage-policies`

Creates an immutable policy bound to exact build/artifact/selected attestation, scenario, manifest, required sink classes, interceptor profile, optional call-site inventory, and one `EffectCoverageBasis`. `INDEPENDENT_BOUNDARY_INTERCEPT` and `TRUSTED_BUILD_INVENTORY_PLUS_INTERCEPT` require a reviewed interceptor profile that covers the complete declared process-tree/sink boundary. `DECLARED_HOOKS_ONLY` is allowed for diagnosis but every complete-effect predicate evaluates REVIEW. The server rejects a claim that inventory alone is complete.

### `POST /__routespec/v1/effect-callsite-inventories`

Accepts a bounded immutable inventory generated by a pinned compiler/plugin or binary scanner and binds analyzer identity, source/build/artifact/manifest digests, enumerated call sites/sinks, and unsupported dynamic/reflection/native findings. A trusted inventory is created only when an enrolled launcher/CI principal attests the analyzer and exact build inputs through a single-use challenge. A direct caller upload is retained, if accepted, only as `DECLARED_HOOKS_ONLY`; it cannot satisfy a complete-effect predicate.

### `POST /__routespec/v1/attester-principals`

Enrolls an attester trust root only after authenticated control-plane access and a distinct explicit local confirmation. `LOCAL_LAUNCHER_KEY` requires reviewed launcher artifact digest, public key, OS peer-binding requirements, validity window, and policy digest; the private key never enters RouteSpec. `CI_OIDC` requires pinned issuer/signing-key policy, audience, repository ID, workflow ref, ref/subject policy, maximum token/key age, and validity window. Case tokens cannot call this endpoint. The response contains principal/policy identity, never a private key.

### `POST /__routespec/v1/attester-principals/{principalId}/revoke`

Requires explicit local confirmation, disables new challenge use, increments the revocation epoch, and records an append-only reason code. Historical attestations remain immutable, but any new or in-progress evaluation that requires the revoked principal becomes REVIEW. Re-enrollment creates a new principal identity; it does not clear revocation.

### `POST /__routespec/v1/launcher-challenges`

Creates a single-use challenge with scope `BUILD_REGISTRATION`, `CASE_LAUNCH`, `EFFECT_INVENTORY`, or `EFFECT_INTERCEPTOR_LAUNCH` for one enabled, unexpired attester principal and current revocation epoch. Build registration binds exact project/build/artifact/lock/toolchain/effect-manifest/adapter identity before GateRun creation. Case launch additionally requires the selected build attestation plus exact gate/case/session/client/epoch identity. Inventory scope binds the pinned analyzer and inventory digest to the build inputs. Interceptor scope binds the reviewed interceptor artifact/profile, sandbox/process-tree/sink scope, gate/case/session/epoch, and private-channel peer identity. The nonce is returned once over the principal's authenticated channel; only its digest persists. A case token alone cannot request or complete trusted attestation.

### `POST /__routespec/v1/launcher-challenges/{challengeId}/complete`

The trusted launcher completes over its inherited OS-authenticated pipe with signature, peer/process/executable identity, and independently calculated digests; CI supplies a signed OIDC token whose issuer/key, audience, subject, repository, workflow, ref, commit, run/attempt, time, and nonce claims match the enrolled policy. Verification checks principal enabled state, revocation epoch, signature/key freshness, challenge expiry/single use, and all scope-specific artifact/manifest/analyzer/interceptor identities. Build-registration success creates an immutable build attestation; case/inventory/interceptor success creates separate immutable records and never mutates the build or GateRun. Mismatch, stale/revoked claims, unavailable peer binding, expiry, replay, copy, or concurrent completion fails closed to user-asserted/REVIEW. Neither proves source correctness or repository protection.

### `GET /__routespec/v1/projects/{projectId}/matrix`

Returns the bounded project/revision/build/attestation/gate-run/corpus matrix with verdict, `artifactReady`, and `enforcementMode` as independent fields. Official live-dry compatibility is a separate axis and never upgrades the local verdict.

### `POST /__routespec/v1/scenarios/validate`

Validates an uploaded YAML/JSON body under strict size limits. It performs no network access and persists nothing unless `persistDraft` is true. Response includes schema errors, compiled digest, resource estimate, and source-provenance warnings.

### `POST /__routespec/v1/scenarios`

Stores a validated scenario revision. Existing revisions are immutable. A changed definition creates a new digest/revision.

### `POST /__routespec/v1/corpora`

Creates an immutable corpus revision from exact scenario revision IDs and per-case required invariants.

### `POST /__routespec/v1/gate-runs`

Creates an immutable `GateRun` in `DRAFT`. Required fields include the exact pre-existing build-registration `subjectAttestationId` or explicit `USER_ASSERTED_LOCAL`, plus build/artifact/corpus/effect-manifest/effect-coverage-policy/adapter/evaluator/configuration/mode/parallelism identities. The server creates one ordered `CaseRun` per corpus case in the same transaction. A later case-launch, inventory, or interceptor attestation cannot upgrade this selection; changing any selected identity requires a new GateRun. `LIVE_DRY_PROBE` is not accepted here because official compatibility is separate.

### `POST /__routespec/v1/gate-runs/{gateRunId}/validate`

Resolves build/artifact/attestation, adapter/profile, effect policy/manifest, optional trusted inventory, independent interceptor profile, exact cases, resources, and isolation/reset policy. A missing interceptor, incomplete process-tree/sink scope, unsupported dynamic call site, or declared-hooks-only policy is an explicit REVIEW limitation for complete-effect predicates; validation cannot silently upgrade it.

### `POST /__routespec/v1/gate-runs/{gateRunId}/start`

Starts the bounded case scheduler. The response contains authoritative `ExecutionLifecycle` values plus separate verdicts where evaluated, not reusable tokens. The scheduler starts at most the declared parallelism and never shares a client instance or mutable state between cases.

### `GET /__routespec/v1/gate-runs/{gateRunId}`

Returns exact identities, attestation, bounded-parallelism progress, ordered case-run states, incomplete/recovery/effect findings, aggregate verdict, `artifactReady`, and enforcement mode. It never describes advisory/unverified state as blocking.

### `GET /__routespec/v1/gate-runs/{gateRunId}/cases`

Returns bounded ordered case rows with scenario, lineage role, client/reset state, current fencing epoch, terminal result, and safe recovery finding. Token values never appear.

### `POST /__routespec/v1/case-runs/{caseRunId}/start`

Acquires the case lease, creates a fresh session/client lifecycle, and returns `sessionId`, proxy base URL, stable header values, a one-time execution token, expiry, fencing epoch, and a `CASE_LAUNCH` challenge referencing the GateRun's selected build attestation. When the selected effect policy requires complete coverage, the control plane separately issues an `EFFECT_INTERCEPTOR_LAUNCH` challenge over the attester channel; it never returns the interceptor private IPC credential to the subject. The token is bound to exact build/artifact/gate/case/session/adapter/client identity. A required trusted-launch/interceptor predicate is not satisfied until the corresponding challenge completes; copied token, another client, or concurrent start fails closed.

### `POST /__routespec/v1/case-runs/{caseRunId}/finish-input`

Revokes the execution token, records adapter/client teardown and reset evidence, snapshots the journal, and begins evaluation. Missing teardown/reset evidence yields REVIEW rather than being inferred.

### `POST /__routespec/v1/case-runs/{caseRunId}/abort`

Revokes active tokens, stops new proxy exchanges, records `ABORTED`, and retains evidence. A required aborted case aggregates to REVIEW unless another case establishes FAIL.

### `POST /__routespec/v1/case-runs/{caseRunId}/recover`

Performs fenced recovery: revoke the stale token, increment the case/session fencing epoch, inspect the journal, and return a one-time `RECONCILIATION_ONLY` token bound to the new epoch. It can access only existing run-operation status/reconciliation reads and evaluation; quote finalization, commit, and any second mutation return `RS_RECOVERY_MUTATION_DENIED`. Repeating recovery with the same idempotency key returns the same safe result; a different concurrent recovery conflicts.

### `GET /__routespec/v1/sessions/{sessionId}`

Returns mandatory build/artifact/attestation/gate/case/adapter/effect-manifest/fencing identity, mode, state, counts, progress, result summary, and blocking findings.

### `GET /__routespec/v1/sessions/{sessionId}/events`

Cursor-paginated event query. Filters: run operation ID, logical job digest, phase, evidence class, event kind, and sequence range.

### `GET /__routespec/v1/sessions/{sessionId}/stream?afterSequence={n}`

Server-sent events for progress. Each event contains gate/case/session identity, sequence, event code, safe summary, and a link to persisted detail. Reconnection resumes from a sequence; SSE is not the source of truth.

### `GET /__routespec/v1/run-operations/{runOperationId}`

Returns exact build/gate/case/session/logical-job identity, typed lineage, current phase, quote-request binding, atomic quote finalization if present, one-time commit binding if present, reconciliation observations, attempts, raw provider observations, normalized facts, effect policy/basis, separate subject reports and independent boundary observations, inventory/interceptor coverage findings, evidence classifications, invariant results, and links. It never exposes a partial quote/commit binding. Sensitive locators are masked by default; `reveal=local` requires fresh local confirmation and is never exported.

### `POST /__routespec/v1/effects/observe`

Authenticates with the exact session/case token and accepts `runOperationId`, `effectManifestDigest`, `hookId`, `hookRevision`, `effectId`, `effectType`, `action` (`ATTEMPTED`, `BLOCKED`, or `RELEASED`), `idempotencyKey`, `fencingEpoch`, optional virtual time, and required wall time. Build/artifact/gate/case/session identity comes from the token and must match the run operation and manifest. It records `SUBJECT_REPORTED` correlation only, performs no effect, and can never write an independent boundary observation or satisfy completeness. An exact retry returns the same observation; a changed binding, stale epoch, undeclared hook, copied token, or manifest mismatch fails closed. Missing required-hook observations or evidence of an uninstrumented release yields REVIEW; absence is never treated as safety proof.

### Private interceptor channel (not a public HTTP endpoint)

The independently launched interceptor writes boundary observations only over an inherited authenticated pipe or equivalent owner-only process-local channel established by its `EFFECT_INTERCEPTOR_LAUNCH` attestation. Each message binds interceptor artifact/profile/attestation, effect policy/manifest/inventory, build/gate/case/session/run operation/scenario, sink/effect/action, epoch, sequence, and time. The service verifies peer process identity and current scope before journaling. Control bearer tokens, case tokens, subject hooks, browser code, imported traces, and CI artifact uploads cannot access this channel. Loss of channel, missing teardown, unsupported sink, or incomplete process-tree coverage yields REVIEW; the interceptor redirects only to a no-effect canary or denies the call.

### `POST /__routespec/v1/imports`

Streams a bounded user trace into `CAPTURED_UNTRUSTED`, then through no-network quarantine, in-memory validation, secret detection, escaping, unresolved-material detection, and normalization. The raw source is not copied into ordinary RouteSpec storage. Only a sanitized quarantine representation may persist; a blocked secret-bearing import stores only source digest and safe finding classes/paths/counts. The response never returns suspected secret values.

### `POST /__routespec/v1/case-runs/{caseRunId}/captures`

Captures the current installed-client trace from authoritative persisted exchanges plus separate subject reports and independent boundary observations under exact build/gate/case/session/run/effect-policy/manifest/inventory/interceptor identity. It creates an immutable `INSTALLED_ARTIFACT_CAPTURE` in `CAPTURED_UNTRUSTED`; it cannot accept caller-supplied replacement events or claim that a fixture came from the installed artifact.

### `POST /__routespec/v1/imports/{importId}/mapping`

Saves a review draft mapping for identities, run-operation phases, events, expected/forbidden behavior, and effect coverage. Mapping cannot execute code or fetch URLs. Unresolved material prevents review.

### `POST /__routespec/v1/imports/{importId}/verify-replay`

Runs repeated no-network trial replays under the pinned profile/evaluator and records whether canonical digests are stable. Secret findings, unresolved material, resource failures, or nondeterminism prevent `REPLAY_VERIFIED`.

### `POST /__routespec/v1/imports/{importId}/promote`

Requires exact installed-capture/import identity, explicit immutable review record, clean secret scan, resolved material, deterministic replay check, expected/forbidden behavior definitions, required effect sinks/hooks and coverage limitations, and provenance class. Promotion atomically produces a new immutable scenario revision and a new corpus revision; it never mutates an existing corpus. The corrected installed client must still execute that new corpus through a normal gate run with fresh independent interception before product PASS.

### `POST /__routespec/v1/gates`

Creates a named gate definition pinned to a corpus revision and required invariants.

### `POST /__routespec/v1/gates/{gateId}/evaluate`

Calculates a new immutable evaluation from one exact gate run and its ordered case runs. FAIL dominates; zero started cases is `NOT_RUN`; any incomplete, cancelled, recovery-pending, private, stale, unattested, uninstrumented, declared-hooks-only complete-effect predicate, missing/incomplete interceptor, unsupported inventory finding, unsupported-required, or identity-mismatched case is `REVIEW`; only every required case complete PASS yields `PASS`. It returns the decision independently from `artifactReady`, plus `LOCAL_ADVISORY`, `CI_CHECK`, or `REQUIRED_CHECK_UNVERIFIED`. v2 has no repository-settings verification adapter, never accepts caller-supplied protection state as verified, never configures an external repository, and never claims release blocking.

### `POST /__routespec/v1/compatibility-probes`

Starts a separately authorized `LIVE_DRY_PROBE` for exact build/profile/official-endpoint identity. It is outside the local GateRun and cannot change its verdict. Success creates an `OFFICIAL_ENDPOINT_COMPATIBLE` compatibility record; unknown or failing shape creates `UNKNOWN` or `INCOMPATIBLE`. The probe requires a real memory-only provider credential and sends only a profile-approved `dry: true` request.

### `POST /__routespec/v1/exports`

Creates an export plan and privacy scan. It does not write a file.

### `POST /__routespec/v1/exports/{exportId}/write`

After local confirmation, writes the redacted bundle to an explicitly chosen local path. Existing files are not overwritten without a distinct confirmation.

### `DELETE /__routespec/v1/projects/{projectId}`

Performs a dry-run by default and reports affected records/artifacts. Actual local deletion requires `confirmDigest` matching the dry-run plan. It does not affect repositories or upstream services.

## 5. Supported proxy surface

The exact SDK commit/version, route schemas, material-field registry, and status schema are pinned by `protocolProfileId` at implementation intake. The profile shall enumerate the seven raw statuses `PENDING_DEPOSIT`, `KNOWN_DEPOSIT_TX`, `PROCESSING`, `SUCCESS`, `INCOMPLETE_DEPOSIT`, `REFUNDED`, and `FAILED`; unknown raw values are preserved and fail closed to REVIEW until a reviewed profile maps them.

### Actual-client adapter contract

An adapter revision is validated against the exact pinned official SDK version/commit before it can validate a GateRun. It must:

1. inject stable session, case-run, logical-job, request, adapter, fencing-epoch, and one-time case-token headers into the SDK transport without changing protocol bodies;
2. receive and retain RouteSpec's assigned run-operation identity after quote-request creation, then correlate quote finalization, commit, internal transport retries, and status calls to that same identity;
3. expose SDK-internal retries as new transport request IDs while preserving logical job and run operation;
4. refuse an expired/revoked/mismatched token, another case/build/client, changed material, or second mutation before transport;
5. switch to a newly issued reconciliation-only token after recovery and forbid quote/commit calls;
6. strip every RouteSpec-local header before any live upstream boundary; and
7. revoke tokens, close sockets/timers, release the client lease, and record teardown/reset evidence at case terminal state.

The adapter test matrix runs the real pinned SDK through quote, quote response, first commit, accepted-then-response-loss, SDK-internal retry, status reconciliation, cancellation, expiry, teardown, and next-case isolation. A hand-written substitute client cannot satisfy this contract.

### `POST /v0/quote`

`SIMULATE` / `REPLAY`: the networkless runtime validates the selected profile and may accept mutation-shaped requests only to follow the local scenario; it has no upstream client or provider credential. `QUOTE_REQUEST` creates the run operation from request-known fields and explicitly rejects an assigned deposit address. The first complete accepted response performs `QUOTE_FINALIZATION`, atomically binding quote/correlation identity, returned constraints, response-assigned deposit address, and extensions. Partial or changed/concurrent re-finalization fails closed, while an exact repeat returns the existing finalization.

`LIVE_DRY_PROBE`: the separate adapter requires `dry` to equal boolean `true`. It rejects missing, string-valued, or false `dry` before credential attachment, DNS, or socket creation. An allowed response is shape-validated and redacted. A live committed quote is unsupported.

### `POST /v0/deposit/submit`

`SIMULATE` / `REPLAY`: `COMMIT_MUTATION` requires the assigned run operation and finalized quote. The first accepted call atomically binds method/route, canonical body/material digest, quote digest, response-assigned deposit address, and transaction/signed-material digest before acknowledgement. It may then apply deterministic acceptance, response drop/connection barrier, duplicate handling, refund, failure, or other scenario-defined behavior entirely locally. Exact retry joins; changed/concurrent/second commit fails without rewriting history.

`LIVE_DRY_PROBE`: always returns `RS_MODE_POLICY_DENIED` with `credentialAttached: false`, `dnsAttempted: false`, and `upstreamAttempted: false`.

### `GET /v0/status`

`SIMULATE` / `REPLAY`: `READ_ONLY_RECONCILIATION` requires an existing run operation and returns the scenario's scheduled provider observation. It may append a read observation but cannot create/finalize a quote or commit. A recovery token is accepted here only at its current fencing epoch.

`LIVE_DRY_PROBE`: disabled by default. A future read-only profile may permit an exact status lookup only after privacy review and explicit enablement. It may not broaden to arbitrary addresses.

### Protocol-profile discovery

`GET /__routespec/v1/protocol-profiles/{profileId}` returns supported routes, exact source SDK revision, schema digests, material-field registry with request-known/response-assigned classification, seven known raw statuses, live-dry allowlist, and known compatibility limits.

Unknown 1Click paths never fall through to the live origin.

## 6. CLI contract

Proposed executable: `routespec`.

### Project and revision

```text
routespec project create --name <name>
routespec revision register --project <id> --label <label> --config-digest <digest> [--commit <sha>]
```

### Scenario and corpus

```text
routespec scenario validate <file>
routespec scenario add <file>
routespec corpus create --name <name> --scenario <revision-id> ...
```

### Run and gate

```text
routespec gate run --gate <id> --build <build-revision-id> --artifact <digest> --corpus <id> --effect-policy <digest> --effect-manifest <digest> --mode simulate --parallelism <n> --json
routespec gate evaluate --gate-run <id> --junit <path> --json <path>
routespec case recover --case-run <id> --json
routespec probe dry --revision <id> --profile <id>
```

The CLI uses a reviewed launcher/CI adapter rather than evaluating an arbitrary shell string. It prints per-case proxy/session/header handoff, attestation state, and token expiry without persisting the clear token. An unattested local run remains `USER_ASSERTED_LOCAL` and cannot claim a verified build.

### Import/export

```text
routespec trace capture --case-run <id>
routespec trace inspect <file>
routespec trace verify-replay --import <id>
routespec trace promote --import <id> --review <review-file>
routespec export plan --gate-evaluation <id>
routespec export write --export <id> --out <path>
```

### Stable exit codes

| Code | Meaning |
|---:|---|
| 0 | Decision PASS; artifact readiness remains separate. RouteSpec v2 never asserts verified required-check state, branch protection, repository enforcement, or release blocking |
| 2 | Gate FAIL |
| 3 | REVIEW, incomplete, unknown, not visible, unsupported required case, or NOT_RUN |
| 4 | User/configuration/schema error |
| 5 | Internal error or corrupted state |
| 6 | Safety policy denied an attempted action |

## 7. Export manifest

Every bundle contains:

- format/schema versions;
- project and integration revision identity;
- mandatory subject build/artifact/attestation, gate-run, ordered case-run, session, client/adapter, effect-policy/manifest, selected inventory/interceptor, and fencing-epoch identities;
- protocol profile and official SDK source revision;
- corpus/scenario/evaluator/configuration identities;
- normalized event and evidence manifests;
- invariant and gate results, evidence class/scope/reason;
- independent artifact readiness and enforcement mode, capped at `REQUIRED_CHECK_UNVERIFIED`;
- exact repository, commit, dirty-tree, built-artifact, and workflow identity when present, without a branch-protection/blocking claim;
- installed-capture -> quarantine -> sanitize -> map -> review -> promoted scenario/new corpus -> corrected-client rerun lineage when applicable;
- declared excluded material;
- source provenance and simulation/dry-only labels;
- toolchain identity;
- checksums; no signature claim exists until a signing ADR is accepted.

Raw authorization, secrets, unreviewed trace payloads, browser local state, and full signed transaction material are prohibited.

## 8. Compatibility policy

- Major API/profile version changes may break clients and must fail closed.
- Minor additions cannot change prior field meaning.
- Evaluator behavior changes create a new evaluator revision and invalidate prior PASS for a new gate.
- Protocol-profile changes create a new profile identity; no silent “latest.”
- Deprecated routes remain visible with removal version and migration notes; they do not silently proxy upstream.
