## Real vs simulated vs blocked

Real:

- Pure kernel (`packages/kernel/src`), no I/O; static audit enforces contracts-only imports.
- Journal-backed tests drive the real networkless proxy over loopback HTTP, the M02 case
  supervisor, the M03 scenario runtime, and the M01 SQLite journal; verdicts come only from the
  kernel and are persisted through `persistCaseEvaluation` (T-003, T-019, T-043).
- T-004/T-059 launch the reviewed canary interceptor as a separate process over its inherited IPC
  channel; subject effect attempts hit its loopback sink; denials, canary releases, teardown, and
  channel loss (process killed) are real. No real downstream effect is ever invoked.
- Restart: a journal with an uncertain commit is closed and reopened past its lease; recovery and a
  concurrent recovery attempt run against the real store (process kill itself is M01's T-022/T-023).

Simulated (product domain, labelled): provider behaviour and ground truth come from compiled M03
scenarios. T-018 journals raw statuses through the store's read-only reconciliation API (the path
the proxy uses) so that all seven raw values and unknown values can be fed directly.

Kernel-semantics only (labelled in the tests):

- Counterexamples the journal refuses to create (an accepted second mutation after uncertainty, a
  reissued execution token, an unfenced case) are applied to the real journal snapshot.
- The complete-coverage PASS for INV-04 is shown on the real T-004 journal snapshot with an
  attested build/interceptor and `PROCESS_TREE_ENFORCED` containment supplied as inputs.
- In T-059 and the T-004 escape case, a second interceptor channel is registered through the store
  API with a test-held key to exercise exact duplicates, binding checks, and a coverage finding.

BLOCKED / NOT_RUN:

- **T-004 live complete-effect PASS: BLOCKED.** It needs (1) an OS/container sandbox that confines
  the subject process tree and forces its sinks through the interceptor, and (2) an enrolled
  attester principal issuing `BUILD_REGISTRATION` and `EFFECT_INTERCEPTOR_LAUNCH` attestations
  (no enrollment API exists yet; M08/M11). Live runs on this host are honestly REVIEW or FAIL.
- T-019 and T-043 API (M08) and UI (M09) surfaces: NOT_RUN here; the kernel side is covered.
- Cross-OS runs (Linux/macOS): NOT_RUN (M10 CI matrix).
- INV-09..INV-12 evaluators: not in this revision; required ones report NOT_RUN and the case REVIEW.

## Security / privacy review

- The kernel has no network, clock, randomness, filesystem, database, or model access.
- Subject reports store only the idempotency-key digest; channel keys stay digests (M02).
- Only the interceptor channel key can write boundary observations or coverage findings; case,
  control-shaped, and forged tokens are refused (T-059).
- The optional explanation model sees a redacted, frozen summary without digests or full IDs.
