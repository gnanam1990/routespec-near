## Source of the API shape

The public OpenAPI document `https://explorer.near-intents.org/api/v0/openapi.yaml`
("Intents Explorer API", version 0.0.0), read on 2026-11-13, SHA-256
`eec0c12615083b0b409ec746fac96183b81c7c74359dc7fffecacf62b77ffb5e`. Used from it: bearer JWT
authentication, one request per five seconds per partner, `GET /api/v0/transactions` with
`numberOfTransactions` (1 to 1000), `statuses`, `startTimestamp`, `endTimestamp`, `direction`,
`lastDepositAddress`, `lastDepositMemo`, `search`, `depositMemo`; the response record fields, the
six statuses and the eleven known refund reasons. The document was read without a key. No
authenticated request was made.

## Limits

- The corpus records what the provider's index reported. It proves no loss, no cause and no
  delivery.
- A delay is a lower bound from the first of two looks, in buckets from 15 min to 24 h. A
  terminal record seen once has no observed delay.
- The second look is one request per held swap, five seconds apart, at most `--recheck-max`
  (default 60). The default wait before it is 15 minutes.
- At most `--max-pages` pages are read (default 20, 1000 records each); `truncated: true` in the
  manifest says older records were not read.
- The kernel has no invariant for a second order opened under a new job key while the first swap
  is held. These scenarios do not detect that.

## Owner step: the live import

From the repository root, in PowerShell. The key is typed into a hidden prompt, exists only in
that shell's environment for the duration of the command, and is never printed.

```powershell
$s = Read-Host 'Explorer API key' -AsSecureString; $env:ROUTESPEC_EXPLORER_JWT = [Runtime.InteropServices.Marshal]::PtrToStringAuto([Runtime.InteropServices.Marshal]::SecureStringToBSTR($s)); node --no-warnings packages/incident-corpus/bin/routespec-incidents.mjs import --out packages/incident-corpus/corpora/mainnet-observed-2026-11; Remove-Item Env:ROUTESPEC_EXPLORER_JWT
```

It reads November 2026 (`--start` and `--end` override the window), waits 15 minutes, looks held
swaps up again, and replaces the pending manifest. Expect about 20 minutes. Add
`--recheck-after-sec 0` for a two-minute run that cannot find late successes. Afterwards:

```powershell
node --no-warnings packages/incident-corpus/bin/routespec-incidents.mjs verify --corpus packages/incident-corpus/corpora/mainnet-observed-2026-11
```

```powershell
pnpm exec vitest run packages/incident-corpus
```

Then commit `packages/incident-corpus/corpora/mainnet-observed-2026-11/` and update the counts in
the README snippet below. To run a gate over it, `register` it into a data directory and pass the
printed `corpusRevisionId` to `routespec gate create --corpus`.

### Scenarios from observed incidents

RouteSpec can turn swaps listed by the Intents Explorer API into gate scenarios: swaps that stay
held, swaps that are refunded (with the documented reason), swaps that fail, and swaps that
succeed late. Only the shape is kept: status sequence, a delay lower bound in buckets, and the
refund reason. No address, account, asset, hash or amount is kept, and every scenario uses
invented `.sim` test data.

| Corpus                     | State                                                                                      |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| `mainnet-observed-2026-11` | **Pending.** Needs the Explorer API key. The committed manifest has 0 records and 0 cases. |
| `explorer-shape-fixture`   | Built from 14 hand-authored records in the documented API shape. Not mainnet data.         |

What runs today, with no key and no network:

    node --no-warnings packages/incident-corpus/bin/routespec-incidents.mjs build-fixture --recording packages/incident-corpus/fixtures/explorer-documented-shape.json --out .data/shape-corpus --recheck-after-sec 3600
    pnpm exec vitest run packages/security-suite/test/m50-observed-corpus-gate.test.ts

The second command runs the real gate over the ten fixture-built cases with a client on the
official 1Click SDK. A client that keeps reading status gets PASS. A client that stops after
three reads gets REVIEW, because it never sees the late success reach a terminal status.

The importer is a separate, read-only tool (GET requests to one pinned origin, at most one every
five seconds). The `routespec` gate itself stays networkless. The importer was built from the
public API document and has not yet been run against the real service. Details:
`docs/status/M50.md`, `docs/adr/0028-observed-incident-corpus-and-explorer-importer.md`.
