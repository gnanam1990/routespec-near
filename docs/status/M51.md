## README snippet (for the README stage; README.md is not edited here)

```markdown
### Fidelity matrix: does the real 1Click API still match the pinned profile?

[![fidelity-matrix](https://github.com/gnanam1990/routespec-near/actions/workflows/fidelity-matrix.yml/badge.svg)](https://github.com/gnanam1990/routespec-near/actions/workflows/fidelity-matrix.yml)

RouteSpec tests your client against a local, deterministic copy of the 1Click protocol. The
fidelity matrix checks that copy against the real service. Once a day a scheduled job reads the
official token list and asks the official endpoint for one `dry: true` quote on each of 24 or
more routes. For every route it records only the HTTP status, a compatibility label and a digest
of the response _shape_ (field names and types, never values).

- First real run, 2026-11-13: **no drift**. 24 of 26 routes across 23 chains answered with the
  same response shape the profile pins; 2 routes were refused by the provider (no shape to judge).
  Full table: [`docs/status/M51.md`](docs/status/M51.md).
- At most 40 requests per run, enforced in the adapter process itself; no retries.
- Dry quotes only: no deposit address, no signature, no settlement. No quote is ever written to
  a file, so none can be committed.
- The API token is a repository secret, held in memory by one separately launched process and
  never sent with the public token-list read.
- A red badge means the live API returned something the pinned profile does not describe. The
  job fails and stops there; it opens no issue by itself.

Run it yourself (it contacts the official endpoint, so it asks for an explicit flag):

    pnpm --filter @routespec/live-dry-adapter fidelity:matrix -- --confirm-official-endpoint --out-dir fidelity-out

Exit code 0 means no drift, 1 drift, 3 inconclusive (fewer than 20 routes could be judged).
```
