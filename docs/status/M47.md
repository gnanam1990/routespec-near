## Self-review notes (not an audit)

- No funds: no payable method, deposits refused by near-sdk before any contract code runs
  (tested), and the wasm imports no promise or balance host function (checked at build time and
  in the sandbox suite). A plain NEAR transfer to the account cannot be refused by any contract.
- Trust roots are the owner account, anyone with a full-access key of the registry account (who
  can replace the code), and each attester's key handling. Verifiers can pin attester keys and
  the code hash.
- Storage can only grow through enrolled attesters. A misbehaving attester is revoked; nothing
  is ever deleted.
- The RPC endpoint is trusted for enrolment and revocation state. Signatures are verified
  locally. Responses are bounded in size and time; redirects are refused.
- The certificate does not carry the corpus digest and commit in a form the bundle can confirm:
  they are attested values, read from the journal at signing time.
- Secrets: key material never appears in output, errors, step outputs, or summaries (tested for
  the CLI and the CI step). `certificate keygen` writes the key file with owner-only mode where
  the platform has file modes; on Windows the file inherits the directory's permissions.
- Known gaps: no owner transfer and no upgrade method (redeploy instead); no light-client proof;
  revocation is not retroactive on chain.

## README snippet (for the integration stage)

````markdown
## Release certificates on NEAR

A gate decision can be recorded in public. `routespec certificate publish` verifies an evidence
bundle, signs a certificate for it (bundle digest, gate verdict, corpus digest, client artifact
digest, commit, timestamp) with an attester key, and the `routespec-registry` contract on NEAR
accepts it only if that key is enrolled and not revoked. The registry is append-only and holds no
funds. Anyone with the bundle can then check it:

```sh
node --no-warnings packages/cli/bin/routespec.mjs certificate verify \
  --bundle <bundle.tar> --registry <registry account> --network testnet --attester <ed25519:key>
```

See: exit 0 and `release.decision: PASS` only when the bundle verifies locally, its decision is
PASS, and the registry holds a certificate for exactly this bundle from that attester. A FAIL
exits 2. A missing certificate, a revoked attester, or any mismatch exits 3 with the reason in
`release.findings`. Nothing on chain can turn a local FAIL or REVIEW into a PASS.

What it proves: an enrolled key signed these values for this bundle. What it does not prove: that
the gate was run honestly or that a repository blocks releases on it.

The contract was tested on a local NEAR sandbox node. Deployment and the first certificate are
owner steps: `docs/runbooks/release-certificates.md`. Decisions and limits:
`docs/adr/0029-onchain-release-certificates.md`. Evidence: `docs/status/M47.md`.
````
