## BLOCKED: RP-07 real official dry probe (exact user steps)

Not run by this stage: it needs a provider JWT that only the user can obtain and an explicit
decision to contact the official endpoint. It performs one `dry: true` quote; no committed quote,
deposit, signature or transfer is possible through the adapter.

1. Obtain your own 1Click API JWT through the provider's partner process (RouteSpec does not
   create accounts or tokens). The probe also runs without one (`OPTIONAL_ABSENT`), but the
   provider may then reject or rate-limit it, which is recorded as `UNKNOWN`.
2. Write a dry quote request file, for example `dry-quote.json` (use real asset IDs from the
   provider's token list; `deadline` in the future; `dry` must be `true`):
   ```json
   {
     "dry": true,
     "swapType": "EXACT_INPUT",
     "slippageTolerance": 100,
     "originAsset": "<origin asset id>",
     "depositType": "ORIGIN_CHAIN",
     "destinationAsset": "<destination asset id>",
     "amount": "<base units>",
     "refundTo": "<refund address>",
     "refundType": "ORIGIN_CHAIN",
     "recipient": "<recipient address>",
     "recipientType": "DESTINATION_CHAIN",
     "deadline": "<ISO-8601 time in the future>"
   }
   ```
3. In your own shell (PowerShell shown), set the token without echoing it, then run the probe:
   ```powershell
   $s = Read-Host -AsSecureString 'Provider JWT'
   $env:ROUTESPEC_PROVIDER_JWT = [Runtime.InteropServices.Marshal]::PtrToStringBSTR(
     [Runtime.InteropServices.Marshal]::SecureStringToBSTR($s))
   pnpm --filter @routespec/live-dry-adapter probe:official -- --confirm-official-endpoint `
     --request C:\path\to\dry-quote.json --ledger C:\path\to\compat.sqlite
   Remove-Item Env:ROUTESPEC_PROVIDER_JWT
   ```
4. Exit code 0 means the record is `OFFICIAL_ENDPOINT_COMPATIBLE`; 1 means `UNKNOWN` or
   `INCOMPATIBLE` (see `reasonCode`); 2 means the confirmation flag or request file was missing.
   The printed JSON and the ledger contain only the redacted shape, reason, HTTP status, timing
   and token state. Attach that JSON to `docs/status/M07.md` to move T-020 to PASSING.

## Security / privacy review

- Denial precedes credential, DNS, socket and upstream client on every path; allowance objects
  cannot be forged; the credential is attached only after an authorized TLS handshake to the
  validated address.
- The JWT never appears on argv, in the ledger, in responses, in reports or in serialization of
  the vault; it is read after preflight and deleted from the environment.
- Proxy variables, TLS overrides and extra CA roots cannot influence the connection.
- Known limits: managed-runtime memory is not erased; on Windows a same-user process can read the
  adapter's environment before it deletes the variable; the tripwire observes and does not
  sandbox; status lookups stay disabled.

## README additions (for the final consolidation stage)

> **M07 — Live dry adapter.** `packages/live-dry-adapter` is a separately launched process that
> forwards at most one `dry: true` quote to the pinned official origin, denying every committed or
> fund-moving request before the provider credential, DNS or a socket. Run
> `npx vitest run packages/live-dry-adapter` (T-020 local boundary, T-021, T-038; networkless).
> The real official dry probe (RP-07) is an explicit user action:
> `pnpm --filter @routespec/live-dry-adapter probe:official -- --confirm-official-endpoint --request <file>`
> (see `docs/status/M07.md`). Its result lives on a separate compatibility ledger and never
> changes a local gate verdict.
