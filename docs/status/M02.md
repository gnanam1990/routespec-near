## Real vs simulated vs blocked

Real:

- Loopback HTTP proxy bound to `127.0.0.1` in a separately launched process; real SQLite journal
  files (database + WAL scanned for configured canary bytes: none found).
- T-016 drives the **actual pinned official SDK** in a separately launched subject process: every
  positive step is an `OneClickService` call (`getQuote`, `submitDepositTx`,
  `getExecutionStatus`). Raw HTTP is used only for negative probes (copied token → `RS_TOKEN_REVOKED`,
  other client → `RS_CLIENT_CONFLICT`, other case → `RS_IDENTITY_MISMATCH`, stale epoch →
  `RS_STALE_FENCING_EPOCH`, other adapter revision → `RS_IDENTITY_MISMATCH`).
- Network tripwire in the proxy process: zero DNS lookups, socket connects, client sockets, and
  undici connects (one IP-literal `lookup` from `server.listen`, reported separately); positive
  control proves it detects real attempts.
- Interceptor: real separate process, inherited pipe, journaled boundary frames, teardown and
  channel-loss records.

Simulated (product domain, labelled): provider behavior comes from the compiled M03 scenario
(quote, deterministic response loss, queued statuses, ground truth). The "live boundary" check in
T-016 uses a loopback stand-in origin inside the subject process; no provider was contacted.

Not run / blocked / limits:

- Cross-OS runs (Linux/macOS): NOT_RUN (M10 CI matrix or user run).
- Subject process-tree no-egress: NOT_RUN — needs an OS/container sandbox with process-tree
  instrumentation; no-egress evidence is scoped to the RouteSpec process.
- Interceptor containment: `DECLARED_HOOKS_ONLY` on every platform (no sandbox integrated);
  complete-effect coverage semantics and T-004 are M04's.
- The pinned SDK has no internal retry; T-016's retry is the adapter's transport retry through
  the SDK's own axios pipeline (ADR-0007 §7).
- LIVE_DRY_PROBE (M07), T-020/T-021: not part of M02; no 1Click API call, credential, or account
  was used.

## Security / privacy review

- Case tokens stored as digests only; tokens travel over IPC, never argv/env; the adapter's
  transport log omits the token; the interceptor channel key is stored as a digest only.
- Provider `Authorization`, `Proxy-Authorization`, and cookies are stripped and counted, never
  recorded; configured canary values in bodies are rejected before persistence with category and
  path only (the value is never echoed).
- Browser `Origin` requests are refused; the proxy never serves the console.
