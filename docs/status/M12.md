## What runs, and how (all real unless stated)

`pnpm run test:delivery` (`vitest.delivery.config.ts`, about 50 s here):

1. **Clean install (RP-01, T-054).** `git clone --no-hardlinks` of `HEAD` into an empty
   temporary directory; `pnpm install --frozen-lockfile --offline`, `pnpm run build`,
   `pnpm run build:console`, all with every proxy variable pointing at `http://127.0.0.1:9`
   (a closed port), `npm_config_offline=true`, and `ROUTESPEC_*`/`NODE_OPTIONS`/`npm_config_*`
   removed. The tree is clean before install and after build. Built output is searched for the
   author checkout path and the install path.
2. **Journey (RP-02..RP-06, RP-08, T-055)** — `packages/delivery/src/journey.ts`, started as its
   own process from the clone against the clone's own artifacts and a fresh data directory:
   - control service through its real entry point (`--handoff ipc`; token only over IPC);
     loopback bind, 401 without the token;
   - project, revision (exact commit), baseline build (artifact digest = SHA-256 of
     `baseline-client.ts`), effect manifest with a REQUIRED no-effect canary sink
     (`fulfilment-canary`), declared-hooks-only policy, reviewed core scenario
     `accepted-then-lost-response`, corpus requiring INV-01..INV-04, `LOCAL_ADVISORY` gate;
   - baseline gate run: a separately launched subject process (pinned official SDK + adapter)
     quotes, commits; the proxy accepts and drops the response; the client resubmits twice
     (both refused, `RS_TOKEN_REVOKED`) and gives up. Kernel: REVIEW, INV-03 missing
     `ACCEPTED_TERMINAL_STATUS`, INV-06 REVIEW;
   - recovery probe (separate case, M02 subject harness, single SDK calls): recovery revokes the
     EXECUTION token, epoch 1 -> 2, issues one RECONCILIATION_ONLY token for
     `READ_ONLY_RECONCILIATION`; stale token status read and commit -> `RS_TOKEN_REVOKED`; second
     commit and a new quote under the reconciliation token -> `RS_TOKEN_PHASE_DENIED`; read-only
     status under it -> allowed;
   - capture of the baseline case (`INSTALLED_ARTIFACT_CAPTURE`, SANITIZED, no findings),
     proposed mapping from the source scenario (`INDEPENDENTLY_REPRODUCED`, provider timeline
     PROCESSING -> SUCCESS), mapping saved, replay verified (3 identical trial digests, one in a
     separately launched process, fidelity MATCH, no network), 8-decision review with the
     confirmation phrase, promotion to a new scenario and a new corpus (base corpus unchanged);
   - the baseline build on the promoted corpus: both cases still not PASS (INV-03 REVIEW);
     inherited case labelled BASELINE, promoted case PROMOTED_REGRESSION;
   - the corrected build (different artifact digest, own build registration, manifest, policy),
     fresh subject process, client instance, case and run operation per case: after the lost
     response it never resubmits, waits for reconciliation authority, and reads status to
     SUCCESS. INV-01, 02, 03, 05, 06, 07, 08 PASS on both cases; **INV-04 REVIEW**
     (`EFFECT_COVERAGE_MISSING`, `UNATTESTED_BUILD`; missing `BUILD_UNATTESTED`,
     `DECLARED_HOOKS_ONLY`, `REQUIRED_SINK_UNOBSERVED`; the promoted case also

## Red/green account (honest)

Real product defects found by the M12 runs, each fixed in product code:

1. **Capture of a synthetic schedule lost its provider timeline** (regressions). The first
   journey's corrected build passed the base case but stayed REVIEW on the promoted case: the
   promoted scenario had been built from the observed trace (`derivedFrom: OBSERVED_TRACE`), which
   held only what the failing client saw (no status read, no ground truth), so the corrected
   client polled `KNOWN_DEPOSIT_TX` eight times. Cause: `proposeMapping` copied the source
   scenario's `SYNTHETIC` provenance, which `validateMapping` rightly refuses for a trace
   (`PROVENANCE_NOT_APPLICABLE`), and the API fell back. Red test 2/2 failed; fix in ADR-0017 §7;
   green 2/2; journey promoted case now passes everything but INV-04.
2. **Re-run of the captured build labelled CORRECTED** (control API). The baseline build on the
   promotion corpus had its inherited case labelled CORRECTED. Fixed (ADR-0017 §8); T-055 asserts
   `BASELINE` + `PROMOTED_REGRESSION`.
3. **Console bundle embedded absolute build paths** (console build). Under an inherited
   `NODE_ENV=test` the build used the development JSX transform with `fileName` paths of the
   build machine. Found by T-054 (`apps/console/dist/assets/index-*.js`); the build now forces
   production; the bundle is byte-identical to a normal build.
4. **Export overwrite under load** (runner). Baseline `pnpm run check` failed T-057 once with
   `RS_EXPORT_WRITE_FAILED` on the confirmed overwrite (passes alone). The rename retry window is
   now about 8 s with back-off (ADR-0017 §9).

Test-side corrections: the T-052 token expectation now normalises the minifier's `.875rem`; the
journey looks case runs up through their gate run (there is no `GET /case-runs/{id}`).

The T-055 assertions that INV-04 is the only non-PASS predicate of the corrected build would
fail if the corrected client regressed (it did, before fix 1) or if INV-04 passed without
runtime evidence.

## Security and privacy review (this team)

- No provider credential, account, wallet, or real endpoint was used. No network route existed
  during install, build, or the journey (closed proxy, offline package manager, networkless
  runtime). The only browser is headless Chromium against 127.0.0.1.
- Tokens cross only IPC pipes; none reaches argv, environment of children, disk, logs, the
  bundle, browser storage, or the DOM (12 canaries scanned).
- The clean-verification directory and the clone are temporary and removed after the run
  (`ROUTESPEC_DELIVERY_KEEP=1` keeps the clone for inspection).
- Not done: an independent security review (M11, NOT_RUN).

## Product independence (deliverable 6)

- `git grep -il dockside -- ':!docs/spec'` -> no match (exit 1): Dockside appears only in the
  sealed specification's disclosure text. No `file:`/`link:` dependency in any package manifest
  (exit 1). RouteSpec has its own repository, state, and code.
- Official event rules: **NOT_RUN**. They must be refreshed immediately before any
  human-authorized publication or submission (`docs/USER-NEXT-STEPS.md`).

## Known limits and remaining work

1. `WORKING_LOCAL` needs trust-rooted subject/interceptor identity and complete independent
   boundary coverage. None exists on this host: no process-tree sandbox, no interceptor process,
   and the standalone service accepts only `USER_ASSERTED_LOCAL` builds over HTTP (the local
   launcher attestation of ADR-0013 needs a launcher the control host forks itself). BLOCKED.
2. One coverage policy per gate run, bound to one scenario revision: other scenarios in the same
   corpus also report `POLICY_IDENTITY_MISMATCH` under INV-04 (ADR-0017 §12).
3. A declared-hooks-only capture can be promoted with its limitations labelled; RP-08 asks for
   such captures to be rejected for release evidence. The lineage can never reach
   `CORRECTED_RUN_PASSED` from it on this host, but the promotion itself is not refused.
4. Only win32/x64 and headless Chromium. Linux, macOS, Firefox, WebKit, touch, screen readers,
   remote CI, container-host access, and the independent security review are NOT_RUN.
5. Termination at the export boundary is not a separate kill test (writes are tmp + exclusive
   link or confirmed rename; T-057 covers failed writes).
6. Recording, publication, and submission: NOT_RUN (needs explicit human authorization).
