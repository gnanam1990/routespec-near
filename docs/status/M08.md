## Real vs simulated vs blocked

- **Real:** loopback sockets and raw HTTP requests carrying exactly the attacker-controlled
  headers; the journal and every constraint/trigger; the proxy exchanges made by the official
  SDK in a separate subject process; kernel evaluation and gate aggregation; lease expiry and
  fenced recovery (journal clock advanced through the store's injected clock); Ed25519 and ES256
  signatures computed and verified with `node:crypto`; the launcher as a separate process over
  an inherited IPC pipe; export bundle written to a real file; the control service as its own
  process with a real restart (T-045).
- **Simulated (by design):** provider behavior comes from the networkless scenario runtime
  (SIMULATE). The CI issuer is a key pair generated in the test; no CI system or OIDC issuer is
  contacted. Launcher build inputs other than the artifact (lock/toolchain/manifest digests) are
  synthetic test values; the artifact digest is computed by the launcher from the real file.
- **NOT_RUN / BLOCKED:**
  - A hosted CI OIDC token: the policy requires the `nonce` claim to bind the challenge nonce
    and observed digests. Whether the M10 action can obtain such a claim from a hosted issuer is
    open (ADR-0013 §9). No real token was used.
  - Interceptor-launch attestation is implemented (private-channel principals only) but not
    linked to an interceptor instance registration; a process-tree sandbox does not exist on
    this host, so coverage is never reported COMPLETE.
  - Physical deletion/purge of a project (M11 retention scheduler); confirmed deletion is
    logical (`deleted_at_ms`).
  - Official dry compatibility probe through the API: refused with `RS_PROBE_NOT_AUTHORIZED`;
    RP-07 stays the M07 operator runbook (user JWT and explicit action required).
  - SSE stream endpoint (`/sessions/{id}/stream`) not implemented; console polls (ADR-0008 §7).
  - Run-operation detail and import detail/lineage responses do not yet match the console
    schemas (`zRunOperation`, `zImportDetail`); the other console shapes are served (parity test).
  - Linux/macOS runs.

## Red/green account

The implementation was written before most tests. First runs exposed these failures, all fixed:

- T-037: the HTTP parser itself answers 400 to a request without `Host` (the test expected 403;
  both are refusals before any handler — test corrected). Path traversal attempts were answered
  with the console shell from inside `dist/` (the test first expected 404 — test corrected and
  now asserts the journal file is never served).
- T-045 setup: scenario selector `*` was rejected by the manifest schema (product fix: selectors
  accept `*`). The case-start idempotency record still carried a `token` key and the store's
  secret guard refused it, which left the key PENDING after the case had started (product fix:
  the record keeps only `tokenDelivery`, and a failed record write no longer hides a completed
  mutation's response).
- T-045 design: keyset paging on `(created_at_ms, uuid)` could skip a project created in the
  same millisecond with a smaller id; listings were changed to `rowid` order before the test ran
  green (commit order under the single writer).
- T-044: recovery reported the post-fence epoch as `previousEpoch` (product fix); the
  proposed-mapping endpoint returned a draft built from the synthetic source scenario that did
  not match the observed trace (product fix: fall back to a trace-derived draft when the source
  plan does not validate).

## README snippet for the consolidation stage

```md
### Local control API (M08)

`node packages/control-api/src/main.ts --data .data --console apps/console/dist` starts the
loopback-only control service (127.0.0.1) and prints a one-time console URL whose `#token=`
fragment carries the ephemeral control token. All `/__routespec/v1` requests need
`Authorization: Bearer <token>`; mutations need `Idempotency-Key` and, for updates, `If-Match`.
Host, Origin, and Fetch-Metadata are checked on every request; no CORS is granted to other
origins. Attester enrollment and revocation need a second local confirmation code printed by the
service. See `docs/adr/0013-local-control-api.md`.
```
