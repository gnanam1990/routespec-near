## Real vs simulated vs blocked

- **Real:** the `routespec` CLI as a separate OS process; the reviewed launcher (`runWithLauncher`)
  delivering credentials only over the inherited IPC pipe; per-case fresh subject processes
  (official SDK + adapter) that the launcher starts separately; the loopback proxy, supervisor,
  journal (SQLite WAL on real files), kernel evaluation, gate aggregation and persistence; real
  process termination (SIGKILL / TerminateProcess) inside the case and gate persistence
  transactions; real files for reports and bundles; bundle verification in a separate process
  with a different working directory and home directory and no journal.
- **Simulated (by design):** provider behavior and ground truth come from the networkless scenario
  runtime (SIMULATE). Two subject builds exist only as test artifacts: `reconciling-client.ts`
  and `naive-client.ts`. `refund-shortfall` is a test variant of the reviewed
  `incomplete-deposit-refund` core scenario (refund 300000 of a 400000 deposit) used to obtain a
  genuine kernel FAIL (INV-05 unexplained loss).
- **Pure-function evidence:** T-034 part 1 and the per-field identity check in T-012 drive the
  production aggregator with explicit GateRun/CaseRun states; every case result in those
  fixtures is a closed `CanonicalCaseResult` digested by the production digest function. The
  end-to-end parts of the same tests run the real product path.
- **NOT_RUN / BLOCKED:** T-012 attestation sub-cases (user self-completion, unenrolled key, bad
  signature, OIDC issuer/audience/repository/workflow/ref/subject/commit/run/nonce, expired
  token/JWK, revoked principal, unavailable peer binding, swapped interceptor, replay, concurrent
  completion) need attester enrollment and challenge verification, which do not exist yet
  (M08/M11). The `REQUIRE_TRUSTED` gate policy keeping a user-asserted build REVIEW is tested.
  Linux/macOS runs NOT_RUN. Trace CLI commands (`trace capture|verify-replay|promote`) are not in
  this stage (the library exists in M05). NFR-04 large-gate timing (100 cases / 10,000 events)
  NOT_RUN.

## Security and privacy review (this module)

- No command executes shell strings, package scripts, or project binaries. The launcher starts
  only the RouteSpec CLI entry point and strips proxy variables and `ROUTESPEC_PROVIDER_JWT`
  from the child environment.
- Clear case tokens never reach stdout, stderr, files, or argv (asserted in T-046); only the IPC
  pipe carries them.
- `LIVE_DRY_PROBE` is refused for gate runs and `probe dry` before anything is created.
- Exports: blocked plans store no content; canaries are absent from stdout, stderr, and the
  journal database/WAL (T-041). Bundles exclude run envelopes and mask addresses by default.
- Caller-supplied branch-protection or blocking claims are rejected; enforcement is reported
  `verified: false, blocking: false`.

## README snippet for the consolidation stage

> **Release gates (M06).** `routespec gate create` pins a corpus and enforcement mode
> (`LOCAL_ADVISORY`, `CI_CHECK`, or `REQUIRED_CHECK_UNVERIFIED`; never verified or blocking).
> `routespec gate run` creates an immutable gate run and hands each case to your client through
> the reviewed launcher (`runWithLauncher` from `@routespec/cli`); it never runs your commands.
> `routespec gate evaluate --json <f> --junit <f> --sarif <f>` writes reports from one persisted
> evaluation. Exit codes: 0 PASS, 2 FAIL, 3 REVIEW/NOT_RUN, 4 configuration error, 5 internal or
> corrupted state, 6 safety policy denial. `routespec export plan|write|verify` produces and
> checks a redacted, checksummed (unsigned) evidence bundle; artifact readiness never changes the
> decision.
