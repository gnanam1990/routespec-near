### Finding, stated plainly

**No invariant finding. RouteSpec could not evaluate this example.**

- The example's first call is the token list, `OneClickService.getTokens()`. RouteSpec's
  `oneclick-v0` profile classifies `GET /v0/tokens` as unsupported and answers 404. The example
  catches the error, prints it, and stops, so it never requests a quote. With no quote there is no
  run operation, and the kernel has nothing to judge. The verdict is REVIEW. It is not a PASS and
  it is not a FAIL.
- This is a limit of RouteSpec, found by running an official example: a client that reads the
  token list before quoting cannot be checked today. It is not a defect in the example.
- Even past that call, this example sends `dry: true`, so as published it would never submit a
  deposit. It is an SDK walkthrough, not a production client. RouteSpec makes no claim about how
  it would handle a lost deposit-submission answer.
- The example's manifest names SDK `0.1.1`. It was run with `0.1.26`, the only version the
  RouteSpec adapter attaches to.

## Why only one repository

The search took about one hour (GitHub repository search and the organisations
`defuse-protocol`, `near-examples`, `near`, `aurora-is-near`). Ten repositories were read at a
recorded commit; the table with licence, SDK use, and the decision for each is in
`examples/third-party/README.md`. In short:

- `near-examples/near-intents-examples` (`32247f923f1b`) is the closest match and uses SDK
  `0.1.26` exactly, but it has **no licence**: no licence file, no licence field, and a README
  that says only that the project is provided as educational examples. It was left out by the
  licence rule.
- `nikshepsvn/near-hydra` (`53aee00b5121`, Apache-2.0) and `IkerAlus/x402_1CS_gateway`
  (`44074be19b1a`, Apache-2.0) use the official SDK but are small personal repositories (6 stars
  and 1 star), so they are neither official nor well known.
- `defuse-protocol/nearintents-mpp-sdk`, `defuse-protocol/defuse-frontend`, and
  `aurora-is-near/intents-swap-widget` are official and MIT, but they do not call 1Click through
  the pinned official SDK in a form that can run as a RouteSpec subject.

## Third-party example clients

RouteSpec also runs example code that it did not write. Each example is named by repository and
commit in [`examples/third-party/pins.json`](examples/third-party/pins.json), fetched on request,
checked byte for byte, and run only inside the subject container. Nothing from the other
repository is stored here.

| Example                                                                                                                            | Commit         | Licence | Result on 2026-11-13                                                          |
| ---------------------------------------------------------------------------------------------------------------------------------- | -------------- | ------- | ----------------------------------------------------------------------------- |
| `examples/basic-swap-flow.ts` of [the official 1Click TypeScript SDK](https://github.com/defuse-protocol/one-click-sdk-typescript) | `ae8b24e06478` | ISC     | Gate REVIEW. No invariant was evaluated: the example stops at its first call. |

What happened: the example first asks for the token list (`GET /v0/tokens`). RouteSpec's local
1Click service serves the quote, deposit submission, and status routes only, so it answered 404.
The example printed the error and stopped before asking for a quote. That is a limit of
RouteSpec, not a defect in the example, and RouteSpec reports REVIEW rather than PASS.

One repository met the rules (public, official or well known, permissive licence, uses the
official SDK). Nine others were read and left out; the closest one, `near-examples/near-intents-examples`,
has no licence. The list and reasons are in [`examples/third-party/README.md`](examples/third-party/README.md).
