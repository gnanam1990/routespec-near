# ADR-0013 — Local control API, attestation, and build matrix

- Date: 2026-11-12. Decision owner: M08 stage, pending user review.
- Status: ACCEPTED (local scope)
- Related: FR-01, FR-02, FR-13, FR-17, FR-18, NFR-02, NFR-09, NFR-11, INV-12; owned tests T-037, T-044, T-045; ADR-0007, ADR-0008, ADR-0009, ADR-0010, ADR-0012.

## Context

M08 adds the mandatory loopback control API used by the console (M09) and later CI (M10). M01–M07 already provide the journal, proxy, kernel, regression pipeline, gate runner, and the separate live-dry adapter. TDD.md lists Fastify as "decision to confirm". The journal has attester, challenge, and attestation tables (migration 001) but no repository code for them.

## Decisions

1. **Transport.** `node:http` with an explicit route table and zod `.strict()` request schemas (`packages/control-api`). No web framework: the pipeline is small, every guard is visible in one file (`server.ts`), and no new runtime dependency is needed.
2. **Bind and browser boundary.** Bind only the literal `127.0.0.1` or `::1`; anything else is refused before a socket opens, and the bound address is re-checked after listen. Every request (static assets included) must carry a `Host` from the generated local origin set (DNS-rebinding defence). A present `Origin` must be the exact service origin (`null` refused). `Sec-Fetch-Site` other than `same-origin`/`none` is refused. No `Access-Control-Allow-*` header is ever sent; `OPTIONS` is refused (same-origin pages never need a preflight).
3. **Control authentication.** An ephemeral `rsctl_` bearer token is generated per service start, kept in memory, compared by digest in constant time, and accepted only in `Authorization: Bearer`. Query-string, cookie, Basic, and case tokens (`X-RouteSpec-Case-Token` or an `rsct_` bearer) are refused. Unknown routes answer 404 only after authentication. Failed authentications have their own rate-limit window; when it is exhausted every request gets 429. The console is opened with `#token=` (fragment only, never sent to a server; ADR-0008).
4. **CSRF.** Mutations require `application/json` (not a CORS-simple type), the bearer header, and `Idempotency-Key`; administrative/project/import updates also require `If-Match`. Gate runs have no counter column, so their optimistic revision is the lifecycle step (`DRAFT`=1 … terminal=6).
5. **Idempotency.** New table `control_idempotency` (migration 007). A PENDING marker commits before the handler runs; the safe response replaces it afterwards. Same key and body replays the stored response (`idempotent-replay: true`); a changed body is `RS_IDEMPOTENCY_KEY_REUSED`; a PENDING marker seen later means the earlier outcome is unknown and is never re-executed (`RS_IDEMPOTENCY_IN_PROGRESS`). A handler that fails before any effect releases its marker. One-time secrets are never stored: case start and recovery keep `tokenDelivery` instead of the token, CI challenges keep `nonce: null`. A replay therefore never re-delivers a token or nonce.
6. **Project scoping.** Scenario/corpus revisions, manifests, policies, inventories, interceptor profiles, principals, and gate definitions are content-addressed and global in the M01 schema. `project_records` binds them to projects; every handler checks the binding and answers `RS_NOT_FOUND` for another project's record. Project deletion is a dry run until `confirmDigest` matches the plan; confirmed deletion sets `deleted_at_ms` (records hidden, journal rows retained). Physical purge belongs to the retention scheduler (M11).
7. **Build registration** stays `USER_ASSERTED_LOCAL` (schema check in the journal). Any caller field claiming an attestation class, verification, or protection is an unknown field.
8. **Attester enrollment and revocation** need a second, out-of-band local confirmation: the first request returns 202 with a confirmation id; the single-use code goes only to the host's local confirmation sink (stderr of the service by default, a callback in tests) and only its digest persists (`local_confirmations`). Policies hold public material only (`attester_policies`; a JWK with `d` is an unknown field). Revocation disables the principal, increments its revocation epoch, appends `attester_revocations`, and leaves historical attestations untouched; new challenges and new gate-run selections fail with `RS_ATTESTER_UNAVAILABLE`, and views show such attestations as `REVOKED`.
9. **Challenges.** `launcher_challenges` + `challenge_bindings` + `challenge_outcomes`. Completion runs in one transaction: an unknown challenge or wrong nonce leaves it untouched; once the nonce matches the challenge is consumed whatever the verdict, so a replay, a copy, or a concurrent second completion can never produce a second outcome (`RS_CHALLENGE_UNAVAILABLE`). Success inserts a new immutable `subject_attestations` row; nothing updates a build or a gate run. A `CASE_LAUNCH` attestation is linked by setting `sessions.case_launch_attestation_id` once (new trigger).
   - `LOCAL_LAUNCHER_KEY`: Ed25519 public key plus the reviewed launcher artifact digest. The nonce goes only over the inherited IPC pipe of a launcher the host forked itself (`ControlServer.attachLauncher`); the host measures the launcher script before forking; the signed payload binds challenge, nonce, scope, binding digest, observed digests, peer pid, and the launcher digest. HTTP completion for this kind is `RS_PEER_BINDING_UNAVAILABLE` and leaves the challenge unused. The private key stays in an operator key file the service never reads.
   - `CI_OIDC`: pinned issuer and ES256 signing keys (no discovery, no network), audience, repository id, workflow ref, allowed refs, subject, maximum token and key age. The token's `nonce` claim must equal `digest(challengeId, nonce, observedDigests)`, so the CI-reported digests are covered by the issuer signature. The M10 action must produce that claim; whether a hosted CI issuer can carry it is open (see status).
   - Interceptor-launch attestation is accepted only from a private-channel launcher principal.
   - Scope digests are compared exactly; extra digests are `OBSERVED_DIGEST_OUT_OF_SCOPE`.
10. **Effects.** A coverage policy that claims complete coverage needs a registered interceptor profile with `PROCESS_TREE_ENFORCED` containment covering every required sink; `TRUSTED_BUILD_INVENTORY_PLUS_INTERCEPT` additionally needs an attested inventory without unsupported findings. Interceptor profiles are always `DECLARED_UNREVIEWED`. A direct inventory upload is `DECLARED_HOOKS_ONLY`; an attested inventory is bound to its content digest (computed without the attestation id) and is reported as supplemental, never as a replacement for runtime interception. The views never report coverage as `COMPLETE`. `POST /effects/observe` authenticates with the case token only and records `SUBJECT_REPORTED`; no public route can write boundary observations.
11. **Cases.** The API caller is the reviewed launcher: `POST /case-runs/{id}/start` returns the one-time execution token and headers; `finish-input` tears down and evaluates through the kernel; `recover` performs fenced recovery after an expired lease (or hands over the reconciliation-only token the supervisor issued after an unknown outcome) and returns it once. GateService gained additive methods for this (`openProxy`, `startExternalCase`, `finishExternalCase`, `abortExternalCase`, `recoverForReconciliation`) and the supervisor `adoptFence`.
12. **Pagination.** Opaque cursors authenticated with a per-process HMAC key; a cursor binds its list and a digest of its filters. Events page by session sequence; other listings by SQLite `rowid` (append-only, never deleted, so rowid order is commit order). Both orders are assigned by the single serialized writer, so rows committed after a page was read always sort after it. The events endpoint always returns a resume cursor (a short page is not the end of a live session). Cursors from before a restart fail with `RS_CURSOR_INVALID`.
13. **Compatibility probes** from the control API answer `RS_PROBE_NOT_AUTHORIZED` (compatibility `NOT_RUN`): the official dry probe stays the separately authorized operator run of the M07 adapter.

## Consequences

- Migration 007 is additive; journal schema version is 7.
- New error codes: `RS_CONTROL_AUTH_REQUIRED`, `RS_CONTROL_AUTH_INVALID`, `RS_METHOD_NOT_ALLOWED`, `RS_IDEMPOTENCY_KEY_REQUIRED`, `RS_IDEMPOTENCY_IN_PROGRESS`, `RS_PRECONDITION_REQUIRED`, `RS_CURSOR_INVALID`, `RS_RATE_LIMITED`, `RS_LOCAL_CONFIRMATION_REQUIRED`, `RS_LOCAL_CONFIRMATION_INVALID`, `RS_ATTESTER_UNAVAILABLE`, `RS_CHALLENGE_UNAVAILABLE`, `RS_ATTESTATION_REJECTED`, `RS_PEER_BINDING_UNAVAILABLE`, `RS_PROBE_NOT_AUTHORIZED`, `RS_DELETION_PLAN_MISMATCH` (CLI exit classes updated).
- The console's `schemas.ts` shapes are served for settings, projects, matrix, gate run, case page, case start, session, events, recovery, and import rows (parity test). Run-operation detail and import detail/lineage are not yet aligned.

## Invalidation

Revisit if the console moves to another origin, if cookie or header-based browser auth is introduced, if SSE with authentication is added, if a hosted CI issuer cannot carry the nonce binding, or if a process-tree sandbox becomes available (interceptor coverage could then be verified, not only declared).
